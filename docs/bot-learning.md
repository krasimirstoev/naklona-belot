# Обучение на ботовете на процесора

Системата подготвя и оценява модел за **цялата игра**: обяви, контри, карти,
комбинации и белот. Обучението е експеримент; създаден файл с тегла не означава,
че ботът е по-силен. Непроверени модели не се включват в сайта.

## Подготовка

Изисква Node от проекта и Python 3.12 на Linux. В отделната среда се инсталира
CPU PyTorch; сайтът няма Python зависимост.

```bash
python3 -m venv .venv-training
.venv-training/bin/python -m pip install -r training/requirements.lock
npm run test:training
npm run bots:learn -- profile --minutes 0.1
```

Профилът измерва само игровата среда със средни ботове. Трудните учители,
мрежата, записването и обучението добавят разход. По подразбиране има два
постоянни Node процеса и две PyTorch нишки. Node процесите изпълняват ходовете
паралелно; резултатите се обработват в постоянен ред.

## Ръчни сесии

```bash
npm run bots:learn -- collect --run data/learning/run-1 --minutes 2
npm run bots:learn -- pretrain --run data/learning/run-1 --minutes 1
npm run bots:learn -- train --run data/learning/run-1 --minutes 2
```

Повторението на команда възобновява сесията от същата директория. `collect`
събира примери от средни и трудни ботове; `pretrain` обучава предпочитание за
избрания от учителя ход. `train` изисква поне една начална обучителна стъпка,
след което използва наградата от самоигра, без задължително следване на учителя.
Всички команди, които играят или обучават, изискват положителен `--minutes`.
Лимитът е за работния цикъл; стартиране, вече започнати ходове и записване
могат да го надвишат. Няма автоматично фоново обучение.

`Ctrl+C` и `SIGTERM` завършват започнатите ходове и записват състоянието.
На всеки приблизително 30 секунди също се прави запис. Атомичният
`checkpoint.pt` съдържа мрежата, Adam оптимизатора, случайните генератори,
ограничените буфери с примери, замразените модели, конфигурацията, метриките и
незавършените игри. `candidate.json` е текущият модел; `metrics.jsonl` съдържа
обобщени показатели. Една директория допуска само една обучителна команда.
При срив на процеса се използва последният завършен запис.

Параметрите `--workers` (1–8), `--threads` (1–8) и `--seed` се задават при първото
стартиране и се повтарят при възобновяване. Промяна на игровия двигател,
кодирането или конфигурацията изисква нова директория; не смесваме несъвместими
данни. `.pt` файловете са доверени локални тренировъчни файлове, а не формат за
качване през приложението. Те съдържат и скритите карти за възстановяване на
средата; тези карти никога не се подават като признаци на мрежата.

## Среда, действия и награда

`training/environment.ts` говори JSON по стандартния вход/изход и извиква
съществуващите `newGame`, `view` и `applyAction`. Събира взятките и преминава към
следващото раздаване автоматично. Четири паса, висящи точки и капо следват точно
правилата на двигателя. Частичен мач не е победа или загуба.

Кодирането v1 има 1752 признака за наблюдението и 81 за кандидат-действието.
То съдържа собствената ръка, публичните бройки, текущия договор и множител,
резултата и висящите точки, цялото наддаване в текущото раздаване, реда и
играчите на всички изиграни карти, победителите във взятките и видимите анонси.
Местата са спрямо играча. Идентификатори, произволен текст, чужди ръце и тестето
не се кодират. Правилата за липсващи бои могат да се научат от историята;
тактическите евристики не ограничават модела.

Действията включват всички разрешени обяви или карта с всяко валидно подмножество
неприпокриващи се комбинации и разрешените варианти за белот. Празното множество
и необявяването на белот също са допустими. Невронната мрежа избира само между
тези действия. Архитектурата е MLP с два ReLU слоя по 128 неврона и линейна
оценка на двойката наблюдение/действие.

Началното обучение използва cross-entropy за ходовете на учителя. Самоиграта
използва Deep Monte Carlo: средноквадратична грешка между оценката на избрания
ход и крайния резултат **+1 за победа на отбора, −1 за загуба**. Това е адаптация
на подхода от [DouZero](https://github.com/kwai/DouZero), не гаранция за неговите
резултати в белот. Междинните картови точки не се използват като заместител на
победата. Има 10% изследване на случаен допустим ход.

В 75% от мачовете текущият модел управлява един играч с отделен замразен
партньор; в останалите управлява и партньора. Другите играчи се избират измежду
среден бот, труден бот и до четири последни замразени модела. Нов модел влиза в
пула на всеки 20 завършени тренировъчни мача. Учителят/противникът на трудно ниво
в обучението използва четири завършени симулационни партиди с голям предпазен
времеви лимит, за да намали зависимостта от натоварването. При оценяване се
използва реалното трудно ниво с бюджет 220 ms. Резултатите не са битово
възпроизводими при промени в Python/PyTorch, хардуера или изчерпан предпазен лимит.

Буферите пазят до 20 000 примера от всеки вид. При самоигра примери с награда
влизат в буфера само след край на мача. Използват се партиди по 64 примера,
Adam с learning rate 0.001 и ограничаване на нормата на градиента до 5.

## Износ и независима оценка

Първо изнасяме отделен файл, който няма да се променя при следващо обучение:

```bash
npm run bots:learn -- export --run data/learning/run-1 --output data/models/experiment-1.json
npm run bots:learn -- evaluate --model data/models/experiment-1.json --report data/eval/dev-1.json --split validation --partner hard --seeds 20 --minutes 2
```

Оценяването също е на ръчни възобновими сесии. Повтарянето със същите аргументи
продължава от същия ход. Съхранява отчета и частното състояние в съседен
`.progress.pt` файл. Промяна на модела, референтния бот или параметрите изисква
нов отчет. Ползвайте **validation** за избор и настройване. Семената за
обучение, validation и final са отделни пространства, независимо от числовия seed.

Когато моделът е избран, окончателните проверки са:

```bash
npm run bots:learn -- evaluate --model data/models/experiment-1.json --report data/eval/final-1.json --split final --partner hard --seeds 1000 --minutes 2
npm run bots:learn -- evaluate --model data/models/experiment-1.json --report data/eval/crossplay-1.json --split validation --partner medium --seeds 200 --minutes 2
```

Тези команди се повтарят, докато отчетите станат пълни. **Две минути не стигат
за 1000 семена.** Пълната проверка включва 4000 мача срещу трудните ботове плюс
800 мача за съвместимост със среден партньор и може да изисква много сесии.
Не използвайте final отчета за подбор между множество кандидати или настройване
на същия модел. При последваща изследователска работа е нужен нов независим
финален набор; версията на пространството от семена се сменя изрично в средата.

За всяко семе моделът заема последователно четирите места при еднакво начално
раздаване. Партньорът е фиксиран според командата; двамата противници са трудни
ботове. Записват се победи, показатели по договори и време на избора в
TypeScript. 95% интервалът се изчислява с 2000 bootstrap извадки на **цели
семена**, а не на отделните четири мача. При непълна оценка няма квалификация.

Предимство се приема само при пълен final отчет с поне 1000 семена и долна
граница над 50%. Отделният crossplay отчет трябва да съдържа поне 200 пълни
семена. Той е допълнителна диагностика; не доказва качество на партньорството с
човек. За това е необходим и игрови преглед.

## Включване и връщане към стария бот

```bash
npm run bots:learn -- promote --model data/models/experiment-1.json --report data/eval/final-1.json --crossplay data/eval/crossplay-1.json
BELOT_MODEL_PATH=/absolute/path/to/experiment-1.json npm start
```

`promote` отказва непълни/неуспешни отчети, различни тегла, променен референтен бот
и непреминала проверка за време (p95 до 220 ms). Създава `.approval.json` до
точния модел; файлът с тегла е обвързан с SHA-256. Това не стартира сайта и не
сменя активния бот автоматично. Моделът се използва само за трудно ниво при
изрично зададен `BELOT_MODEL_PATH`, в development и production worker-а.

Сайтът проверява формата, размерите, крайните числови стойности, версията на
кодирането и съответствието с отчетите. При липсващ, непроверен, несъвместим или
отказал модел, както и при превишен бюджет за зареждане и избор, worker-ът
използва предишния труден бот. Премахването на `BELOT_MODEL_PATH` връща изцяло
предишното поведение. Публичните действия, интерфейсът и базата не се променят.

## Проверки

```bash
npm test
npm run test:training
npm run build
```

Node тестовете не изискват PyTorch. Python тестовете проверяват числено
съвпадение на мрежата, наградите, обновяването на теглата, възобновяването на
оптимизатора/генераторите/частичната игра и статистическото групиране по семена.
Кратка успешна тренировъчна сесия доказва работещ цикъл, **не по-силен бот**.
